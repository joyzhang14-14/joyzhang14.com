Sparky-toolbox

A personal agent harness for the NVIDIA DGX Spark, optimized for local models.

Python · Linux · MIT · GitHub

Prompt-injection defense

A verified quote shows where an answer came from, not that it is harmless. The other layers assume the agent can still be misled:

  • Sandbox. A throwaway container with a read-only root, no Linux capabilities and no network except the gateway, which allows only the task's tools.
  • Tools. A separate unprivileged user with network limited by Landlock. A broker checks every container against what the tool declared.
  • Shell. Each command is dry-run first under Landlock and seccomp. Side-effect-free commands then run read-only; the rest need my approval.
  • Outbound. Replies go only to me. Email recipients come from a fixed list, and links must come from the run's sources. Outgoing data is scanned for credential values, and the browser checks where each address it opens came from.
  • Approval. Browser submissions, uploads, personal details and every note edit need my approval. Passwords are filled from a card the model never sees.
  • Data. Credentials never enter the sandbox. Downloads are marked untrusted and only isolated readers may open them. Memory is scanned for injection phrases, hidden Unicode and secrets.
